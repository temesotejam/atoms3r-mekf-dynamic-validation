# V46ae / 0.46.30 — 振幅制御をMEKFへ統一

## 変更の目的

V46adまでは、ゼロクロスとピークの到達判定にMEKFを使いながら、
ピーク振幅を `abs(0.908911 * integral(gy - startup_bias))` で求めていた。
この積分は測定開始から継続し、MEKFによる姿勢・バイアス補正が反映されなかった。
今回の3 ms Runでは、終盤の符号付き積分角とMEKF相対角の差が約+2.03°になった。

V46aeはAutonomousのピーク振幅、目標誤差、P1入力、次のパルス計算を
補償前のMEKF測定開始相対角に統一する。ゼロクロスには選定済みの3 ms補償を使う。

| 用途 | V46aeの値 |
|---|---|
| ピーク時刻・左右 | 補償前MEKF相対角の極値と、MEKFバイアス補正済み角速度の戻り3サンプル |
| ピーク振幅 | `abs(pitch_mekf_measurement_relative_deg)` を上記極値で保存 |
| 目標誤差・積分補正 | `target_peak - MEKF_peak`、正負別の既存Ki=0.10を維持 |
| 自由減衰予測・パルス幅 | 上記MEKF振幅を既存P1と基本Q1ゲインへ入力 |
| ゼロクロス | `theta_MEKF_relative + omega_MEKF * compensation_s` |
| 角速度・出力方向 | `(gy_dps - mekf_bias_y_dps) * MEKF_GYRO_Y_SCALE` |

MEKFの角度を数値微分して角速度を作るわけではない。角速度にはMEKFが推定した現在の
ジャイロバイアスを反映する。0.908911は既存のMEKF入力校正として1回だけ適用され、
MEKF出力角を再び0.908911倍する処理はない。
測定開始姿勢を0°とする定義は維持し、動画の水平基準角とは区別する。

## なぜ従来のジャイロ積分が残っていたか

確認できた履歴は次のとおり。

1. 2026-09-04の保存済み `ENERGY_CONTROL_AUTONOMOUS_V7_V45_CURRENT_AUDIT_FIRMWARE_20260904.zip`
   には、MEKF導入前から独立した積分振幅がある。左右応答補正の設定には
   `V6_three_run_closed_loop_20260904` と記載され、計算座標は `firmware_scaled_gyro_peak` だった。
2. [2026-09-12のV46移植](https://github.com/temesotejam/atoms3r-mekf-dynamic-validation/commit/f253f0aba3a60775aa690af1ab17afd05218d5ec)
   は、このV7の振幅・モデル経路を引き継いだ。MEKFは採用姿勢になったが、
   振幅入力まで全面的に置き換えた実装ではなかった。
3. 過去の会話でも、MEKF導入後に積分振幅を残した理由として、既存のモデル・左右補正との
   座標整合を先に維持する方針が説明されていた。初期の不具合修正では半周期検出、
   パルス方向、ログ、取得周期、遅延を順に扱い、振幅変更は別の課題として残っていた。
4. [2026-09-13のV46f](https://github.com/temesotejam/atoms3r-mekf-dynamic-validation/commit/7a1d6f933534d7c27341cf474fcb572e37f0b60d)
   は、同じ0.908911をMEKFのYジャイロ入力にも適用した。
   これはセンサ入力の校正であり、V7の独立積分をMEKF出力へ交換する変更ではない。
5. [V46ac](V46AC_LIGHT_DELAY_COMPENSATION.md) と
   [V46ad](V46AD_DELAY_COMPENSATION_SWEEP.md) は遅延評価を目的に、積分振幅とモデルを維持した。

したがって、**MEKFでは振幅を計算できないため残していたのではなく、旧制御モデルと
当時の比較条件を引き継いだ結果**と確認できる。
以前の「MEKFを制御へ採用」という説明だけでは、振幅に旧経路が残る点が十分に伝わらない。

ただし、MEKF導入以前に「最初になぜ累積ジャイロ積分を選んだのか」については、
保存V7ソース・同梱資料・取得できた会話から、当初の比較結果や選定理由まで特定できなかった。
加速度の動的汚染やフィルタ遅れを、記録の裏付けなしに当時の採用理由と断定しない。
半周期のピーク間積分による半振幅と、測定開始からの累積積分の絶対値も別方式である。
また、P1/Q1の基礎係数がすべて積分角だけから同定されたとは断定しない。
直接確認できるのは、従来P1への振幅入力とV7左右補正の実行座標が積分角だったことである。

## 古い左右補正を無効化する根拠

保存5 Runの測定10〜30秒で、元のピーク時刻を使ってMEKF相対ピークを取得し、
記録されたQ指令を与えた1ステップ予測を比較した。旧ファームウェアの実際のP1・Q1関数を
ホストで実行し、MEKF入力に旧左右補正を適用する場合と、基本P1/Q1だけの場合を比較した。

| Run | 評価数 | MEKF入力＋旧左右補正：RMSE | MEKF入力＋基本P1/Q1：RMSE |
|---|---:|---:|---:|
| 補償なし c489 | 46 | 1.945° | 1.553° |
| 3 ms 30b7 | 47 | 1.721° | 1.311° |
| 6 ms d5af | 47 | 1.422° | 1.167° |
| 9 ms 1292 | 46 | 1.088° | 0.782° |
| 旧Quaternion予測 2ad2 | 45 | 1.535° | 1.147° |

全Runで旧左右補正を外す方が誤差は小さかった。これは旧制御で得たQと運動を用いた
オフライン計算であり、新版を動かした閉ループ性能や、P1/Q1再同定の完了を意味しない。
基礎モデルにも誤差が残るため、既存係数は初回実機比較用の基準として維持する。
同じデータへの新しい左右係数の当てはめは行っていない。

旧左右補正は `ENERGY_CONTROL_AUTONOMOUS_SIDE_RESPONSE_CORRECTION_ENABLED=false` とし、
由来と係数は履歴確認用に残す。正負別の目標誤差積分（Ki）とは別物であり、Kiは有効のまま。

## 記録と検証

- RWLOGはv51。同じ258 byteサンプル構造を維持し、振幅・角速度の意味の変更をmetadataで識別する。
- `peak_amplitude_deg` は補償前MEKFピークの絶対値、`detector_peak_angle_deg` はその符号付き値。
- ゼロクロスイベントの角速度はMEKFバイアス補正・入力校正後。旧Q1のraw軸の適用範囲も
  同じ校正率で換算して診断する。診断範囲外を理由とした新しい出力制限は追加しない。
- 古い形式のRWLOGも変換可能。比較Madgwick、生IMU、ジャイロ積分の診断ログ、LED同期は維持。
- ジャイロ積分角をAutonomousへ入力する経路と専用積分状態は除去。
- 同じジャイロサンプルを複数回処理しても、ピーク確定の3サンプルを水増ししない。
- MEKF角度・角速度が非有限値なら、既存ESTOP処理へ進む。
- 300 mA、最大100 ms、起動パルス、実半周期制約、IMU取得と10 ms遅延停止を維持する。

`tools/test_v46ae_mekf_amplitude.py` は本番のmotion/peak/error-feedback/model関数を抽出して
実行し、両側ピーク、補償時間からの振幅独立性、バイアス・経過時間、重複サンプル、
パルス中抑止、非有限値停止、旧左右補正の無効化を確認する。
既存の回帰ゲートでは、明示したV46ae差分だけを逆変換し、未変更部分の旧ハッシュを保持する。
これは新版の全制御が旧版と同じという主張ではない。新版の動作は別の実行テストで確認する。

## 最初の実機測定

遅延補償3 ms、目標8°で30秒。開始姿勢と撮影条件をそろえ、各Run終了後にRWLOGと動画を保存する。
最初は2 Run程度で、ピークログと動画の一致、左右差、目標誤差、飽和・無出力、
周期・電流タイミングを確認する。水平基準と開始相対基準の動画値を別々に評価する。
MEKF振幅に変更した新版の閉ループ結果は、実機データを取得してから判断する。
