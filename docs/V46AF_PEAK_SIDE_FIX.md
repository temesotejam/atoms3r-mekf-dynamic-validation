# V46af / 0.46.31 — 無出力時のMEKFピーク追跡を修正

V46aeの初回実測d170は、MEKF振幅を制御に使っていました。ただし動画にある負側ピークが
3回、制御イベントから抜けていました。補償後の角度でゼロクロスを受理した直後に、
補償前MEKFが旧側に残るケースを本番関数で再現し、V46afで修正しました。

## 実測条件と比較

両方とも3 ms・目標8°・30秒。動画の固定水平基準で、10〜30秒のピークを比較します。

| 指標 | 旧3 ms（30b7） | V46ae（d170） |
|---|---:|---:|
| 正側ピーク平均 | +8.259° | +8.156° |
| 負側ピーク平均 | −8.232° | −8.608° |
| 目標±8°に対するRMSE | 0.361° | 0.797° |
| 目標から±0.5°以内 | 80.9% | 25.5% |
| 動画ピーク数（全30秒） | 70 | 70 |
| 制御ピーク数（全30秒） | 70 | 67 |
| 指令→3 mA電流変化の中央値 | 3.282 ms | 3.279 ms |

各条件1回なので再現性の統計ではありません。開始姿勢基準の動画振幅で比較しても、
RMSEは0.611°→0.860°です。MEKFへの統一が済んだことと、8°に精度よく制御できることは
分けて評価する必要があります。

d170の全67ピークで `peak_amplitude_deg == abs(detector_peak_angle_deg)` と
`peak_error_deg == 8 - peak_amplitude_deg` が記録精度内で成立しました。
全通常ゼロクロスの旧残差補正値は0です。動画と対応する10〜30秒の45ピークでは、
制御MEKFと開始姿勢基準の動画ピークの符号付き差は平均−0.191°、RMSE 0.200°でした。
これは「MEKFの計測が約0.2°違う」指標であり、「目標8°への制御誤差0.797°」とは別です。

RWLOG CRCと添付manifestの3ファイルのSHA-256は一致。IMUは12143取得・12143配信、
欠落・キュー落ち・faultは0、最大取得間隔3.860 ms、電流読出し失敗0でした。
ただし制御処理の2.5 ms予算超過は144/12144回、最大5.917 msありました。
動画同期はLEDの36遷移で照合、残差RMS 7.826 ms。約30 fpsの動画から数msの電流開始遅延は
独立に確定できません。電流時刻は読出し完了時刻で、物理的な立上りそのものではありません。

## ピーク抜けと修正

動画の負側ピーク約8.772秒・19.068秒・24.201秒に対応する制御ピークがありません。
それぞれ直前のゼロクロスイベント21・44・55は `VALID_NO_OUTPUT` でした。
これは停止やログ容量不足ではありません。

1. ゼロクロスは3 ms先読みした角度で受理する。
2. 無出力ならピーク追跡を直ちに再開する。
3. その時点の補償前MEKFが旧側に残っていると、旧側の小角度を次の候補として固定してしまう。
4. 本来の次側ピークを確定できず、反対側まで待ってしまう場合がある。

V46afは `pending_next_side` とMEKF角の符号が一致するまで候補を作りません。
ゼロクロスの予測角をピーク振幅に使う変更はしていません。
既存の3サンプル戻り確認、125 msのゼロ〜ピーク間隔、パルス中の検出抑制は維持します。

変更対象はピーク追跡の方向条件です。P1・基本Q1・Ki、3 ms、電流上限、最大パルス幅、
起動パルス、非常停止、IMU取得はV46aeのままです。

## 検証と限界

本番のmotion/peak/record関数を使うホスト試験で、旧側+0.10°、速度−60°/sの開始から
次の負側−8°ピークを入力すると、V46aeは0ピーク、修正後は1ピークを記録しました。
正負両側と0/3/6/9 msの回帰ケースを `tools/test_v46ae_mekf_amplitude.py` に追加しました。
既存の過去ハッシュは保持し、明示した方向条件とrevisionだけを逆変換して未変更部分を確認します。

この修正はピーク抜けの再現ケースを解消します。今回の振幅ばらつき全体を説明した、あるいは
修正後の実機精度が改善した、とまではまだ言えません。基本モデルの予測残差も残っています。
MEKF移行と旧残差補正無効化が同時に入ったため、今回だけで各変更の効果も分離できません。

## 次の測定

V46af / 0.46.31を書き込み、**3 ms・8°・30秒**を同じ開始姿勢・撮影条件で測定します。
各RunのRWLOGと動画を次の開始前に保存してください。
まず動画ピークと制御ピークが正負交互に対応することを確認し、その後P1/Q1の残差と振幅の
ばらつきを評価します。現時点では3 msを変更する理由はありません。

MEKF移行とジャイロ積分を残していた経緯は
[V46AE_MEKF_AMPLITUDE.md](V46AE_MEKF_AMPLITUDE.md) に記録しています。
