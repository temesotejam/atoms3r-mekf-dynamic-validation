## 確定したソフトウェア上の不具合

`logSampleNow()`は先にmicrosを保存し、後でtelemetrySnapshotを読み、さらにcurrentAgeUs内で別snapshotを読む。
Core0が途中でpublishすると、(1)参照時刻より新しいサンプルを引くuint32アンダーフロー、(2)電流値・取得時刻・ageの異なるsnapshot混在が発生する。
元コードの読み順で両方を決定的に再現するnativeテストを追加した。実機内部の全タスク切替を直接トレースしたという意味ではない。

修正はスナップショットを1回だけコピーし、その後でmicrosを採り、同じコピーの取得時刻を差し引くこと。
巨大値を0へ丸める処理、再読出しループ、長いcritical section、新しいI/Oは追加しない。
既存の取得時刻0=未取得、age=UINT32_MAXという約束は維持する。同期アンカーでは行時刻を規約上0へ上書きする既存例外も維持する。
32-bit時刻の通常の折り返しはunsigned差で扱う。約71分以上の差を一意に復元する機能はない。
未使用となる旧currentAgeUs APIはドライバ互換性のため残すが、ログからは呼ばない。

`test_v46t_current_observation.py`は実際の本体から読出し/時計/ageの文を使用し、10万通りの模擬publishタイミング、欠測、0年齢、読出し失敗、wrapを検査する。
ログ部分の厳密な逆変換後にV46s全文のSHA-256が一致すること、さらに従来のV46s監査除去後にV46r全文のSHA-256が一致することを維持する。
既存のモータ/IMU/MEKF/ワーカ/通常226バイトサンプルの保護ハッシュは変更しない。

## ピーク座標のずれは4 Runで再発、補正方法は未確定

動画LEDのみで同期し、生angle_absolute_degの極値を比較。角度のゼロ点、振幅、位相を合わせるフィットは行っていない。
ピーク付近160 ms窓の局所極値を隣接3点で補間。正負側を同じ重みで平均した「機体内の符号付き積分ピーク - 動画ピーク」は次のように変化した。

| Run | 最初0–5秒 | 共通の19–24秒 |
|---|---:|---:|
| 7e34 / V46l | -0.526° | +2.217° |
| 4bca / V46p | -0.509° | +1.034° |
| 487c / V46q | -0.342° | +1.209° |
| f35a / V46s | -0.459° | +0.486° |

同期に使えたLED遷移は順に36/36/26/36件、最大時刻残差は約35/29/27/48 ms。
これは一定のゼロ点差では説明できない。全区間の線形傾向は約0.143/0.088/0.082/0.057 deg/sでRunごとに違う。
積分座標は起動時の固定gyro biasを差し引いた角速度の累積で、MEKF姿勢そのものではない。再発と累積座標の問題は確認できるが、残留bias・ホスト取得タイミング・姿勢軸投影・動画参照の寄与を分離できていない。
MEKFピークも各Runで動画との固定差や変化があり、そのまま代用すれば全て直るとは言えない。
したがってV46tでは積分座標、ピーク振幅定義、MEKF、左右ゲイン、Kiを変更しない。一定ドリフト値の差し引きも行わない。

## 4–6 ms取得間隔も既存の別課題

全取得監査のあるV46p/V46q/V46sで、5 ms超は98/11791 (0.831%)、108/9474 (1.140%)、89/11718 (0.760%)。
最大取得間隔は5.633/7.774/5.912 ms。V46lの間引き時系列は同じ分母に使わない。
今回だけの現象ではないが、V46tは取得処理を変更しない。10,000 usの配信遅延ESTOPは維持する。

## 実機確認

本変更の新規実機Runはまだない。V46tで同じ条件のRunを保存し、欠測を除くage異常0件・時刻差不一致0件と従来のソルバ時間/停止診断を確認する。
ビルド・nativeテストの成功は、実機での完走や角度ずれ解消の証明ではない。
