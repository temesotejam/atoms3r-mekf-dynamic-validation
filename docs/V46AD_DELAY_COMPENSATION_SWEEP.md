# V46ad / 0.46.29 遅延補償時間の粗探索

> 過去の版の記録です。現在は[V46ajで遅延補償を3 ms固定](V46AJ_FIXED_3MS.md)にしています。

V46acの軽量角速度予測を引き継ぎ、補償時間だけを停止中に選択できるようにしました。

## 操作

1. [書き込みページ](https://temesotejam.github.io/atoms3r-mekf-dynamic-validation/)からV46adを一度書き込みます。
2. 機体の操作画面で、READY_TO_MEASUREまたはFINISHEDになってから遅延補償時間を選びます。表示が確定し、Startボタンが有効になってから開始します。
3. 目標8°、各30秒で次の順に測定します。

| Run | 遅延補償 | 用途 |
|---|---:|---|
| 1 | 3 ms | 前版相当の基準 |
| 2 | 6 ms | 補償を増やした比較 |
| 3 | 9 ms | 粗探索の上端 |
| 4 | 0 ms | 補償なしの対照 |
| 5 | 3 ms | 電池・温度・開始条件などの変化を確認 |

各Runで立位・設置・撮影条件をそろえ、LED同期が見える動画とRWLOGを保存してください。
**次のRun開始で前回の機体内ログは上書きされます。各Run終了後に保存してください。**
再起動すると補償時間は3 msへ戻ります。設定は不揮発保存しません。

## 固定と記録

- 選択可能値は0 / 3 / 6 / 9 msのみです。起動時の初期値は3 msです。
- Run開始時に値をコピーし、開始同期・測定・終了同期の間は固定します。
- 設定はREADY_TO_MEASUREまたはFINISHEDかつダウンロード中でない場合だけ変更できます。ESTOPは従来の解除操作が必要です。
- 設定送信中はStartを無効にします。画面は開始要求に確認済みの値を付け、他画面などから設定が変わっていたら開始を拒否して再確認します。
- RWLOG v50の `autonomous_timing_compensation_us` はそのRunの実使用値です。次の設定を選んでも以前のログには影響しません。
- `autonomous_control_prediction_enabled` はAutonomousかつ補償時間が0より大きい場合だけtrueです。

予測式は次のとおりです（時間は秒）。

```
theta_control = theta_posterior_measurement_relative
              + (gy_dps - mekf_bias_y_dps) * MEKF_GYRO_Y_SCALE * compensation_s
```

0 msでは未補償角をそのまま使います。動画比較用posterior角、Gyro積分の振幅・エネルギー座標、
高速solver、300 mA、最大100 ms、IMU取得と電流記録、停止条件は前版を維持します。

## 比較方法

主評価は10〜30秒の動画ピークで、同じ座標・同じ基準の±8°からの誤差、ばらつき、左右差を比較します。
絶対角と開始時相対角を混ぜず、両方を区別して記録します。最初と最後の3 msに差があれば条件変動を先に確認します。

副評価として、未補償posteriorのゼロクロスに対する指令時刻と、電流変化を初めて観測した時刻を比較します。
電流の記録時刻は物理的な電流開始時刻そのものではなく、動画も30 fpsでは数ms差を直接確定できません。
今回の比較だけで1 ms単位の最適値を確定せず、有望な範囲を絞って追加測定します。
9 msまで改善が続く場合は範囲を広げるか再現測定してから判断します。

## 検証範囲

`tools/test_v46ad_timing_selection.py` は実際のsetter、HTTPハンドラ、予測式、メタデータ式をホストで実行し、
全状態の設定可否、選択範囲、Run固定、保存済みメタデータ、0 ms、設定と開始の競合を確認します。
`tools/test_v46ad_timing_ui.js` は組み込み画面の実際のJavaScriptに遅延応答を与え、古い状態応答・設定失敗・連打を確認します。
既存のcontroller/estimator/IMU/safetyのハッシュ検証は、V46adの明示した差分だけを逆変換し、従来の基準ハッシュを保持します。
既存回帰テスト、PlatformIO実機向けビルド、公開ファイルのコミット・SHA256照合も公開ゲートです。
実機での挙動と最適補償時間は、これから取得するRunで評価します。
