# V46u / 0.46.20 — 時間内処理を優先する検証版

## 目的と現状

角度ドリフト・角度の参照点・MEKF・Madgwick・制御ゲインには手を入れない。V46t Run 5501は完走したが、通常パルスのrunner中央値2.7175 ms・最大5.528 ms、Core1経路最大7.252 ms、全取得間隔最大7.018 msであり、毎回2.5 ms以内の達成とは扱えない。10 ms配信遅延ESTOPが発生しないことは、2.5 msの処理期限達成と別である。

同Runの取得プロファイルは29,548 polls、update API平均537.388 us、capture処理全体平均563.355 us、1 ms以上の処理後のyieldが5,266回。経過時間でありCPU実行時間だけを分離した計測ではない。

## 実際の変更

M5Unified 0.2.18のBMI270 `getImuRawData()`だけをビルド時に検証付きで差し替える。元ファイルのGit blob SHAは `41732382bbdfe413be758748bca24d9a15a3a1d8`。一致しないライブラリを黙って変更しない。パッチ結果と共通ヘッダのSHA-256はビルド成果物へ保存する。

- `INT_STATUS_1 (0x1D)`ではなく、未読を保持する`STATUS (0x03)`のdata-readyを確認する。
- gyroのみなら0x12から6バイト、accelのみなら0x0Cから6バイト、両方なら12バイト。
- 磁気はreadyのときだけ既存の8バイト取得・変換を保持する。
- readyが無いセンサのDATAを触らない。フラグ確認後に別センサの値が更新されても、未使用の読み出しで消費しない。
- 読出し失敗はfreshとして返さず、ドライバエラー件数も診断に残す。

元の20バイト一括読出しより不要なバイトとバス占有を減らす。ただしこの差が実機の全遅延の何割か、改善後に毎回期限を守れるかは新Runが必要。磁気同時取得では2回のDATA転送になる場合があり、全ケースが必ず高速化するという主張ではない。

根拠: M5Unified 0.2.18 `src/utility/imu/BMI270_Class.cpp`、Bosch BMI270 datasheet revision 1.6 (2026-03), sections 4.6.6, 4.6.13, 5.2.3。
STATUS data-readyは対応するDATA読出しでクリアされる。INT_STATUSは割込み状態で、非ラッチ設定での自動クリア等と区別する。テストは仕様に沿った競合を再現するもので、旧実機内部の全バス取引を直接トレースした証明ではない。

## 時間の定義とログ

1. `v46n_imu_acquisition.v46q_poll_profile.v46u_timing`: 1 msのcapture処理予算、2.5 msのホストgyro取得間隔との比較、STATUS/DATA読出し時間、失敗数、転送バイト数。capture処理の終点は従来のelapsed地点で、後続の診断集計コストは既存record_overhead_max_usで別に見る。
2. `v46p_control_worker.v46u_deadline`: RUNNING中に受け取った全fresh gyroについて、ホスト取得時刻からrunner returnまでの年齢と2.5 ms超過を数える。単独solver時間ではなく推定・判断を含む。制御workerのループ待機時間はこの年齢に含まれるが、センサ内部の実サンプル時刻やモータ適用完了までではない。
3. `v46u_current_timing`: パルス中の電流読出し処理と、連続した有効電流の取得間隔を2 msと比較する。既存Q積分とスケジューラは変更しない。この項目の集計範囲は起動後の全パルスでありRun別ではない。複数Runを同じ起動で実施した場合はその制約を保持する。

0件をPASSにしない。超過はstrict > budgetで、許容差を勝手に足さない。全取得・配信・処理件数を照合し、不足を成功にしない。通常RWLOGは従来どおり226バイトの間引き記録で、追加カウンタは全対象を集計する。

400 HzのセンサODRとホストの毎回2.500 msは同じではない。1 msポーリングは保持するため、ホスト間隔には量子化と位相差が残り得る。この版はFIFO/センサ時計監査ではなく、全センササンプル無欠落や厳密なハードリアルタイムの証明をしない。時間を人工的に2.5 msへ書き換えたり重複サンプルを新規取得として数えたりしない。

## 維持するもの

センサ400/200 Hz、1 msポーリング、I2C 400 kHz、取得/制御/HTTPの優先度、キュー32件、過負荷時yield、10,000 usの配信遅延ESTOP、300 mA/100 ms制限を保持。`experiment_runner.cpp`全体とMEKFソースはV46tと同一。時刻記録修正も維持する。追加診断部分を正確に逆変換して従来の保護ハッシュを検査し、保護値を新しいファイルのハッシュへ置換しない。
