# 現在の角度推定 — V46aj / 0.46.35

対象は、このリポジトリの **Autonomousモード**です。
姿勢推定と次ピーク予測はV46ai（`68ff188146f3301228e9283048feb6fb94dac9af`）を継承し、
V46ajで遅延補償を3 ms固定にしました。
現在の識別文字列は `v46aj_fixed_3ms_compensation_20260920` です。
既存のリンクを保つため、この説明ファイルの名前は維持しています。

現在の姿勢は、BMI270のジャイロと加速度をMEKFで組み合わせて推定します。
そこから実験開始姿勢を基準とした角度を作り、ピークの測定に使います。
ZEROクロスの判定には、さらに3 ms先へ進めた予測角度を使います。

「角速度だけに一本化した」のは、**次のピーク振幅を予測する式**です。
現在の姿勢そのものは、引き続きジャイロと加速度によるMEKFで推定しています。

## 1. IMUデータの取得

使用するセンサはAtomS3R内蔵のBMI270で、加速度3軸とジャイロ3軸を使います。
このMEKFへ磁気センサや動画の角度を入力する処理はありません。

| 項目 | 現在の設定・処理 |
|---|---|
| ジャイロ出力レート | 400 Hz設定。測定3943の取得実績は約405 Hz |
| 加速度出力レート | 200 Hz設定 |
| ホストの読み出し確認 | 1 ms周期。毎回新しいセンサ値があるとは限らない |
| MEKFの時間更新 | 新しいジャイロデータごと |
| 加速度による補正 | 新しい加速度データがある場合のみ |
| 計算に使う時間間隔 | ジャイロの実際の取得時刻の差 |

データの更新番号を確認し、同じジャイロデータを繰り返し積分しません。
加速度についても、同じデータで測定更新を繰り返さないようにしています。
時刻はマイコン側の取得時刻であり、BMI270内部のセンサ時計を読み出した時刻ではありません。
ログへの保存周期と、内部の姿勢更新周期は別です。

実装：[imu_manager.cpp](../src/imu_manager.cpp)、[config.h](../src/config.h)。

## 2. 軸・感度・初期姿勢の補正

### 機体の座標へ合わせる

センサの取り付け方向を機体・動画の符号に合わせます。
MEKF入力では加速度・ジャイロともX軸とZ軸の符号を反転し、Y軸の符号を維持します。
MEKFは3次元姿勢を推定し、そのpitch成分を今回の揺動角として取り出します。

Y軸ジャイロには **0.908911倍の感度補正**を入れています。
これはMEKFへ入力する角速度の補正であり、推定後の角度を0.908911倍する処理ではありません。
Y軸のバイアスも同じ座標・感度でMEKFへ渡します。

### 静止時のジャイロのずれを求める

起動時に約5秒間の静止データを平均し、各軸のジャイロバイアスを求めます。
バイアスは、実際には回転していなくてもジャイロが示す角速度のずれです。
この初期値をMEKFへ渡し、その後もMEKF内部でバイアスを推定します。

### 実験開始前に姿勢を初期化する

起動時に機体が横たわっている運用に対応するため、Autonomousの開始同期中に、
安定して直立している加速度を平均してMEKFの姿勢を再初期化します。
平均の判定窓は800 ms、必要な連続安定サンプル数は60以上です。
途中で不安定なサンプルが来た場合は平均用の蓄積をやり直します。
起動時に求めたジャイロバイアスは再設定します。

実装：[experiment_runner.cpp](../src/experiment_runner.cpp) の
`mekfAccelFromRaw`、`mekfGyroRadFromRaw`、`updateStartupCalibration`、`updateStartSync`、
[upright_pose_guide.h](../src/upright_pose_guide.h)。

## 3. MEKFが行っていること

MEKFはMultiplicative Extended Kalman Filterです。
姿勢をクォータニオンで保持し、姿勢誤差3成分とジャイロバイアス誤差3成分の、
計6成分の誤差状態を扱います。

新しいセンサデータごとに、次の処理を行います。

1. **ジャイロで姿勢を進める。** 推定したバイアスを角速度から引き、前の姿勢から最新サンプル時刻の姿勢を計算します。
2. **加速度と照合する。** 現在の姿勢から予測した重力方向と、加速度の向きを比較します。
3. **姿勢とバイアスを補正する。** センサの信頼度と推定の不確かさに応じたカルマンゲインで補正します。

MEKF内部の時間更新にはジャイロの積分があります。
以前の独立した「ジャイロだけを積分した角度」をそのままAutonomous制御に使う処理は、
現在の姿勢・ピーク・ZEROクロスの入力には使っていません。

### 動いているときの加速度の扱い

揺動中の加速度には、重力に加えて運動による成分が含まれます。
そこで、次の2つから加速度の信頼度を求めます。

| 評価する量 | 信頼度を下げない範囲 | 信頼度が0になる値 |
|---|---:|---:|
| 加速度の大きさと1 gとの差 | 0.08 g以下 | 0.30 g以上 |
| 加速度の向きと予測した重力方向の角度差 | 6°以下 | 22°以上 |

中間では余弦関数で信頼度を滑らかに下げ、2つの信頼度の小さい方を使います。
信頼度が低くなると加速度の測定ノイズを大きく扱い、補正を弱めます。
信頼度が0.05未満なら、その加速度による補正を見送ります。

表の「信頼度を下げない」は、加速度の角度へそのまま置き換える意味ではありません。
その場合もカルマンゲインに応じて補正します。固定25%の混合ではありません。
以前の25%という値は次ピーク予測の混合係数で、MEKFの姿勢補正とは別の処理でした。

実装：[mekf6.hpp](../src/mekf6.hpp)、[mekf6.cpp](../src/mekf6.cpp) の
`predict`、`updateAccel`、`smoothConfidence`。

## 4. 角度の基準と用途

実験開始時のMEKF角度を保存し、その後の角度から引きます。

```text
theta = MEKFの最新角度 - 計測開始時のMEKF角度
```

この `theta` の0°は計測開始姿勢です。
開始姿勢が固定水平線から傾いていれば、その分だけ動画の固定水平線基準とは異なります。
動画と比較するときは、固定水平線基準と開始姿勢基準を区別します。

| 用途 | 使用する角度・ログ列 |
|---|---|
| MEKFが推定する連続した姿勢のpitch | `pitch_mekf_abs_deg` |
| 開始姿勢基準の角度・動画比較 | `pitch_mekf_measurement_relative_deg` |
| ピーク振幅の測定 | 予測前の開始姿勢基準MEKF角度の絶対値 |
| ZEROクロス検出 | `pitch_mekf_detector_relative_deg`：遅延補償を加えた角度 |
| Autonomousの制御角度ログ | `pitch_mekf_control_deg`：上記の検出用角度と同じ |

ここで「最新角度」は最新IMUサンプルに基づく推定値です。
プログラムがその値を使う時刻までの取得・処理遅れが、完全になくなるという意味ではありません。

実装：[experiment_runner.cpp](../src/experiment_runner.cpp) の
`beginMeasurementRun`、`captureMekfComparisonZero`、`updateMekfComparisonRelativeAngles`、`updateDisplayedAngles`。

## 5. ZEROクロス用の3 ms先の予測

ZEROクロス検出には、最新の角速度が短時間一定と仮定した予測を使います。

```text
omega     = (gy_dps - mekf_bias_y_dps) * 0.908911
theta_pred = theta + omega * 0.003
```

角速度の単位は°/s、0.003は秒です。
`mekf_bias_y_dps` は起動時の固定バイアスではなく、MEKFが更新しているバイアスを
元のIMU座標・単位へ戻したものです。

例えば `theta = -0.18°`、`omega = +60°/s` なら、
3 ms先の予測角度は0°です。機体が実際に0°へ来る前に判断することで、
判断処理とアクチュエータの応答遅れを補償する狙いです。

遅延補償は**3 ms固定**です。0・6・9 msへの切り替え、画面の選択欄、設定APIは削除しました。
開始時に補償時間を指定する必要はありません。変更点は[3 ms固定化](V46AJ_FIXED_3MS.md)を参照してください。
このAutonomous経路では、サンプルの経過時間を3 msへ追加したり、
別のクォータニオンによる先読みを重ねたりしていません。
3 ms補償だけで、実際の入力が常に物理的なZEROクロスと完全一致するとは保証しません。

### 隣接サンプルの補間

直前と今回の `theta_pred` が0°をまたいだ場合、その2サンプルの間を補間します。

```text
alpha  = abs(theta_pred_before)
         / (abs(theta_pred_before) + abs(theta_pred_after))
omega_cross = omega_before + alpha * (omega_after - omega_before)
```

例えば予測角度が−0.04°から+0.06°へ変われば、`alpha = 0.4` です。
この40%は固定値ではなく、毎回の角度から決まります。
使うのは隣接する2サンプルで、前の周期の角速度ではありません。

補間した角速度は、**予測角度のZEROクロス位置に対応する角速度**です。
3 ms先の実際の角速度を別の運動モデルで予測しているわけではありません。
判断は今回のサンプルを受け取った後に行い、将来のサンプルを待ちません。

実装：[experiment_runner.cpp](../src/experiment_runner.cpp) の
`updateDisplayedAngles`、`updateEnergyControlAutonomousMotion`。

## 6. ピークの検出

ピーク振幅には、3 ms予測を加えていないMEKF角度を使います。

1. 対象となる半周期の側で、開始姿勢基準の角度の絶対値が最大になる点を保持します。
2. 角度の絶対値が保持した最大値より小さくなり、角速度の符号も中央へ戻る方向になったことを確認します。
3. その戻り条件を新しいジャイロサンプルで3回続けて満たしたら、ピークを確定します。

記録する振幅と時刻は、確認完了時の値ではなく、保持していた最大値とその時刻です。
角速度の符号が一度変わっただけではピークにしません。

3 ms予測によるZEROクロスは、予測前のMEKF角度が0°を越える前に発生できます。
そこで次のピーク追跡では、予測前の角度が目的の側に入るまで候補を作らず、
まだ残っている前の側の角度を次ピークとして取り込まないようにしています。

パルス出力中も姿勢推定と検出用履歴の更新は続きますが、
新しいピーク・ZEROクロスを物理制御イベントとして受け付ける処理は抑止します。
半周期の状態管理に従って、ピークとZEROクロスを順番に受け付けます。

実装：[experiment_runner.cpp](../src/experiment_runner.cpp) の
`updateEnergyControlAutonomousPeakTracker`、`updateEnergyControlAutonomousMotion`。

## 7. 次ピーク振幅の予測との区別

| 処理 | 求めるもの | 主な入力 |
|---|---|---|
| MEKF姿勢推定 | 最新サンプル時点の姿勢 | ジャイロ・加速度 |
| 3 ms先読み | 遅延補償したZEROクロス検出用の角度 | MEKF角度・バイアス補正済み角速度 |
| 次ピーク振幅予測 | これから到達するピークの振幅 | 補間したZEROクロス角速度・方向・入力Q |

V46aiで一本化したのは最後の処理です。
基準振幅は角速度と方向だけから求め、そこへ入力Qによる振幅増分を加えます。
前のピーク振幅から予測するP1や、P1へ戻す切り替えはありません。
具体的な式は[角速度式への一本化](V46AI_RATE_ONLY_BASELINE.md)を参照してください。

実測ピークは引き続き記録、半周期の順序管理、目標誤差の積分補正に使います。
これは次ピークの基準振幅をP1から予測する処理とは別用途です。

Madgwick、ジャイロ単独積分角、加速度単独角は比較・診断用として残っています。
現在のAutonomousの姿勢・ピーク・ZEROクロス判定にはMEKF系統を採用しています。

## 8. 実測で確認できたこと

2026-09-19の測定 `20260919_190539_375_3943.zip` は、
V46ai・目標8°・遅延補償3 ms・30秒です。元データはこの説明ファイルには同梱していません。

| 確認項目 | 結果 |
|---|---|
| 計測中の動画とファームウェアのピーク対応 | 69個すべて一対一で対応 |
| MEKFと動画のピーク差 | 開始姿勢基準、10〜30秒の46ピークでRMSE約0.103° |
| IMUの取得・配信 | 各12,142件、配信欠落・キュー落ち0 |
| ジャイロ取得間隔 | 平均約2.471 ms、最大約3.905 ms |

0.103°はピーク値の比較であり、全時刻の角度誤差や3 ms予測の誤差を表す値ではありません。
動画の時刻合わせはLEDの36変化点を使い、残差RMSは約16.8 ms、動画は約30 fpsです。
この動画だけで3 msの真の時間差を精密に検証できたとは扱いません。
動画ピークの数値には局所5点二次近似を使い、波形の比較では角度波形を合わせるための時刻調整をしていません。

同じ区間の目標8°に対するMEKFピークのRMSEは約0.643°でした。
実際の揺れを捉える性能と、入力によって8°へ揃える性能は別の評価です。
現時点では、この姿勢推定を土台に予測モデルと制御則を検討する方針です。
