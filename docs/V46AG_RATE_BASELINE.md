# V46ag / 0.46.32 — 角速度を使う予測補正の実験版

V46afの実測8cdeでは動画70ピークに対して制御も70ピークを記録し、無出力後の
ピーク抜けは確認されませんでした。一方、10〜30秒の動画ピークの目標±8°に対する
RMSEは0.796°で、V46aeの0.797°とほぼ同じです。次は中央通過時の角速度を使い、
次ピークを予測してパルス量を決める処理を改善します。

## 予測候補の比較

3 ms・8°・30秒のd170と8cdeを使い、一方のRunで係数を求め、もう一方のRunで評価しました。
次ピークが10〜30秒にある、入力履歴もそろった共通標本を使用しました。
d170は41件、8cdeは46件です。欠けたピーク・履歴を補完していません。

| 次ピークの予測式 | d170で学習→8cdeで評価 | 8cdeで学習→d170で評価 |
|---|---:|---:|
| 現行P1/Q1（記録値） | 1.064° | 1.007° |
| 中央通過角速度＋既存Qゲイン | 0.177° | 0.215° |
| 角速度＋直前の半周期のQ＋既存Qゲイン | 0.134° | 0.165° |

数値は**MEKFの次ピークに対する一段先予測のRMSE**です。実際に送ったQと、その時点の
状態を入力しています。目標8°への実機制御誤差でも、今回の25%補正版の性能でもありません。
二つのRunから候補を選んだため、独立した新規Runでの確認が必要です。

Qと直前ピーク・角速度は閉ループ中に強く相関しています。Qゲインまで同時に推定すると
Run間で値が安定しませんでした。履歴を使う候補は保存し、今回の制御は単純な角速度式から
始めます。Qゲインは正側0.29032、負側0.25455 deg/(mA s)を維持します。

## 実装

二つのRunの共通87標本で求めた、Q=0相当の有効な予測基準値は次の式です。
純粋な自由減衰の物理モデルを同定した、という意味ではありません。

```text
A_rate_plus  = 7.217460941 + 0.286814471 * (abs_rate_dps - 65)
A_rate_minus = 8.399746959 + 0.130807354 * (abs_rate_dps - 65)
delta = clamp(0.25 * (A_rate - A_P1), -0.5, +0.5) [deg]
A_baseline = max(0, A_P1 + delta)
A_next = A_baseline + g_side * Q
```

補正が有効になる条件は、目標8°・補償3 ms・開始から10秒以上、かつ次の範囲です。
範囲の内側でも、変更後のパルス量の妥当性まで実測保証するものではありません。

| 次側 | 直前ピークの大きさ | 中央通過角速度の大きさ |
|---|---:|---:|
| 正 | 8.3〜9.8° | 61.5〜72°/s |
| 負 | 6.7〜9.0° | 59〜70°/s |

最初の10秒、他の目標・補償時間、範囲外ではP1の値をそのまま使います。
新しい基準値から既存のエネルギー計算・整数パルス幅探索を実行します。
一度に角速度モデルへ全面置換すると未測定のQを多く要求するため、25%・±0.5°で試します。
それでも正側で過去の定常測定範囲を超えるQが選ばれる場合があります。

MEKF、V46afの次側ピーク待ち、3 msの先読み、基本Qゲイン、Ki、300 mA・最大100 ms、
起動パルス、非常停止、IMU取得、LED同期は維持します。

## 記録と検証

RWLOG v51の時系列サンプル配置は維持し、ゼロクロスのJSONイベントと変換CSVに次を追加しました。

| 項目 | 内容 |
|---|---|
| `p1_free_peak_before_rate_deg` | 補正前のP1 |
| `rate_baseline_peak_deg` | 角速度式の基準値 |
| `rate_baseline_correction_deg` | 今回反映した補正量 |
| `rate_baseline_reason` | 0=有効、1=最初の10秒、2=他設定、3=範囲外、4=非有限等、255=未評価 |
| `free_next_peak_amplitude_deg` | パルス計算に実際に使用した補正後の基準値 |

metadataに式・適用条件・学習元を記録します。従来の `correction_deg` は旧Q残差補正の欄で、
今回の補正とは別です。新規ヘッダの本番関数を使い、開始境界・設定・両側・上限・非有限値の
6500ケースを確認しました。過去のハッシュ基準は変更せず、明示した差分だけを逆変換して
既存制御部分を検証します。実機での振幅改善は未確認です。

記録された状態・Ki・電流モデル入力を固定した137判断のPC再計算では、補正は92件で
有効となり、46件でパルス幅が変わりました。補正時の正側最大幅は36 ms、負側は54 msです。
補正前後とも高速探索と全候補探索の結果は137件一致しました。これは閉ループの将来推移を
再現したものではありません。実機が送る幅・Qには、その前の補正による状態変化も影響します。

元の実機選択とは136/137件一致です。8cdeのevent 70は実機17 msに対しPC16 msでした。
PCでは16 msと17 msのエネルギー誤差がともに1.3715471141e-6 Jで同点でした。
17 msのQもPCと実機でfloat32の1 ULPだけ異なります。目標エネルギーのビットは一致しており、
候補計算の丸めと同点判定の境界にある差として記録しました。実機選択の完全一致とは扱いません。

## 次の測定

1. V46ag / 0.46.32を書き込み、**遅延補償3 ms・目標8°・30秒**にします。
2. 開始姿勢・撮影条件をそろえます。最初の10秒は従来制御、その後に条件を満たした場面で補正します。
3. Run後、次の開始前にRWLOGと動画を保存してください。

ピークの対応、補正の適用率、次ピーク予測残差、左右別の目標誤差、Q・パルス幅を確認します。
同一Runの前後比較には立上り・履歴の影響もあるため、前後差だけで効果を断定しません。
V46afの同条件測定とも比較し、良ければ同じ設定で再測定して再現性を確認します。
