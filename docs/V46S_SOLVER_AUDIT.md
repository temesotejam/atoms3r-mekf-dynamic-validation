# V46s / 0.46.18 — ソルバ計測・オフライン検証

基準はV46r `09e6a0ea15cca6b25eba8209ed375bf392229beb`です。V46rの高速ソルバ・無入力比較・制御定数・MEKF・IMU取得・タスク優先度・300 mA/最大100 ms・10,000 usの配信遅延ESTOPは変更しません。V46sの変更は記録と検証です。

## 追加した記録

RWLOGメタデータの`v46s_solver_audit`に、通常の受理済みゼロクロスごとに1件記録します。初回キックはソルバ判断ではないので従来のtiming probeで確認します。無入力、FF計算失敗、補正目標の不正、最終選択失敗、状態・書込失敗も関数を抜ける際に記録します。次ステップでESTOPになっても最後の判断を保持します。ただしRAM記録なので電源断や関数実行途中のCPUリセットに対する永続化ではありません。

| 項目 | 意味 |
|---|---|
| `decision_us` | 判断関数入口から出口まで。記録コピー自体の直前で計測。割込み・プリエンプションを含む経過時間であり純粋なCPU実行時間ではありません |
| `solver_us` | キャッシュ計算開始から選択終了まで。失敗時も終了点を記録 |
| `fast_solver_us` | 以前のV46rの計測値。FF探索から最終選択まで、初期キャッシュ計算を含みません。`solver_complete=1`の場合に有効 |
| `free_model_us` | 自由減衰予測の計算時間 |
| `ff_search_us` / `selected_search_us` | それぞれの高速探索時間 |
| `ff_eval_count` / `selected_eval_count` / `eval_count` | 実際に評価した候補数 |
| `gyro_sequence` / `sample_time_us` | この判断で使用した消費側IMUサンプル |
| `entry_sample_age_us` / `exit_sample_age_us` | 同じ使用サンプルの入口・出口での年齢。生産側の最新サンプルやキュー末尾の年齢ではありません |
| `sample_time_valid` | 時刻の欠測と0 usを区別 |
| `pulse_id_before` / `pulse_id_after` / `t_test_ms` | 同じRun内のパルス・停止診断との対応付け |
| `stage` / `outcome_reason` / `solver_complete` | 計算段階と既存制御の理由コード |
| `ff_width_ms` / `fast_selected_width_ms` / `selected_width_ms` | FF幅、高速探索候補、無入力基準との比較後の最終幅。65535は未計算 |
| `output_executed` / `event_valid` | 計算成功と実出力を区別 |
| `float_fields` / `f32_bits` | 再計算用のfloat32を小数に丸めずuint32ビット列で保存。NaNも保持 |

最新128件を固定長リングで保存し、`overwritten`に上書き件数を明示します。実行中は数値代入と固定サイズコピーだけで、JSON化・全探索・ファイル操作・動的メモリ確保は行いません。JSON化は既存の停止後ダウンロード処理で行います。計測の負荷はゼロとは主張しません。内部の時間項目は重なるので足し合わせないでください。

RWLOG v46・226バイトの通常サンプル構造は変更しません。従来の`v46n_imu_acquisition`と`v46p_control_worker`も引き続き使います。旧`v46l_solver_shadow_policy`の誤った「旧全探索が実制御」の説明を訂正し、旧配列は互換性のため空で残します。取得系サブコンポーネントのV46q表記と、ファームウェア全体のV46s表記は区別してください。

## 停止後のオフライン比較

同じ版のリポジトリをPCへ取得し、Python 3.11以降と`g++`で実行します。

```sh
python tools/replay_v46s_solver_audit.py run.rwlog --out-dir solver-report
python tools/test_v46s_solver_audit.py
```

RWLOGを含む実験ZIP、またはメタデータJSONも入力できます。生RWLOGはCRCを検証します。JSON単体はCRCを確認できないので`crc_ok: null`です。

実際のファームウェアから評価関数と高速探索を抽出してnative float32で再計算し、独立した0〜100 ms全探索と比較します。全探索はPCだけで行います。オンデバイスで計算済みの電流モデル値・応答係数はビット列から復元します。ホストとESP32の数学ライブラリの丸め差までなくなるわけではないため、同点付近の幅差は個別に調べます。不一致を許容誤差で黙って一致へ変換しません。

各RunについてJSON集計と判断ごとのCSVを出力します。`fast_replay_match`・`legacy_ff_match`・`legacy_selected_match`を別々に報告します。失敗・未完了は`not_replayed`、記録上書きは`overwritten`です。0件、欠落、未完了、不一致を`full_comparison_pass: true`とは扱いません。終了コードは0=全記録の比較成功、1=不一致または未完了の報告を生成、2=入力・ツールエラーです。時間統計は実機ログの値でありPCの計算速度ではありません。

## 検証と限界

監査用の挿入を除去した`experiment_runner.cpp`全体が基準版とバイト一致することをSHA-256で検査します。版名以外の設定、IMU、モータ、制御ワーカ、MEKF、サンプル構造も保護します。文字列が含まれるかの検査だけでなく、リングの順序・上書き・リセット、早期return、負の0、時刻wrap、記録メモリ上限、再計算、意図的な不一致、空ログ・旧ログの拒否もnativeテストします。

旧Runの56件は小数に丸められた過去のメタデータです。ホストでは56件の選択幅を再現しましたが、新版の実機検証でも、厳密な入力ビット列の検証でもありません。56件一致は全入力域での同値性の証明ではありません。

## 保存領域

監査リング約21 KBは起動時にPSRAMへ1回だけ確保します。内部RAMの固定使用量を増やしません（ポインタ等の少量を除く）。制御中の再確保はありません。確保できない場合は既存の制御動作を変えず、メタデータに`available: false`と`audit_psram_allocation_failed`を出します。そのログを比較成功とは扱いません。新しい記録の実機負荷は未確認です。
